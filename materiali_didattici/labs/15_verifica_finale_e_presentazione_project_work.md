# Lab 15 - Verifica Finale e Presentazione Project Work

## Obiettivo

- Preparare consegna, discussione tecnica e dimostrazione finale.
- Collegare il risultato pratico al micro-argomento: Valutazione sulle competenze apprese durante il corso.

## Durata (timebox)

- 30 minuti.
- 5 minuti setup e lettura scenario.
- 20 minuti esecuzione guidata.
- 5 minuti checkpoint, cleanup e consegna evidenze.

## Prerequisiti

- Repository project work, materiali prodotti, rubriche di valutazione.
- Conoscenza base di Python, terminale, Git e ciclo di vita del modello.
- Fallback previsto: usare scheda di simulazione locale, tabelle Markdown o screenshot della documentazione quando tool, credenziali o permessi non sono disponibili.

## Scenario

- Il team prepara la verifica finale con prova orale, lavoro di gruppo e prova pratica.
- L'obiettivo e rendere presentabile il project work e collegarlo alle competenze ModelOps del corso.
- Ogni risorsa locale, container o servizio cloud eventualmente creato deve essere chiuso o rimosso a fine attivita.

## Step (numerati)

1. Raccogli repository, notebook, slide, demo e documentazione del project work.
2. Prepara una traccia di presentazione con architettura, metriche e scelte operative.
3. Esegui una prova pratica o simulata del workflow end-to-end.
4. Annota risposte a possibili domande su rollback, monitoring, sicurezza e governance.
5. Verifica cleanup finale e assenza di risorse attive non necessarie.

## Output atteso

- Un file Markdown, notebook, tabella o screenshot commentato con le decisioni prese.
- Evidenze minime su metriche, versioni, logica di deploy, monitoraggio, sicurezza o valutazione finale.
- Nota finale con limiti, fallback usato e cleanup eseguito.

## Checkpoint

- Il risultato risponde all'obiettivo della sessione e non introduce componenti fuori dal micro.
- Le decisioni sono motivate con metriche, vincoli, costi, rischi o impatto operativo.
- Il gruppo sa spiegare cosa cambierebbe passando da prototipo ad ambiente reale.

## Troubleshooting rapido

- Se una libreria Python manca, descrivi il passaggio con pseudo-output e continua con la simulazione locale.
- Se Docker, cloud o dashboard non sono disponibili, usa console, tabella Markdown o screenshot guida come fallback.
- Se un comando resta bloccato, interrompi il processo, annota l'errore e passa alla verifica concettuale.
- Se compaiono dati personali o segreti, rimuovili dal materiale e sostituiscili con valori fittizi.

## Cleanup obbligatorio

- Ferma server locali, notebook kernel, processi FastAPI, container Docker, dashboard o script lasciati in esecuzione.
- Rimuovi immagini, volumi, file temporanei, token, credenziali o dataset copiati quando non servono alla consegna.
- In cloud o servizi a pagamento, elimina endpoint, job, bucket, istanze, dashboard e risorse create per evitare costi.
- Conferma nel deliverable che il cleanup e stato completato o indica cosa non e stato possibile rimuovere.
